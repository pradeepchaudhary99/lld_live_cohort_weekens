01 — Introduction

What is Rate Limiting?

A rate limiter controls the rate of traffic sent or received by a system. It restricts how many requests a client can make in a given time window. Requests beyond the limit are either rejected (429) or queued.

🛡️
DoS Protection
Prevents denial-of-service attacks from overwhelming servers with massive request floods.
⚖️
Fair Usage
Ensures no single user or tenant monopolizes shared infrastructure resources.
💰
Cost Control
Prevents runaway API costs in cloud billing scenarios and third-party API usage.
📊
SLA Enforcement
Tiered rate limits enforce service level agreements — free vs paid plans.
📌 Key Interview Point

Rate limiting can be applied at different granularities: per user ID, per IP, per API key, per endpoint, or globally per service. Always clarify the scope in system design interviews.

03 — Algorithms Overview

Four Algorithms

🪙
Token Bucket
Tokens refill at constant rate up to capacity. Each request consumes 1 token. Allows controlled bursting. Most popular in practice.
🪣
Leaky Bucket
Requests queue up and drain at a constant rate. Excess overflows. No bursting — smoothest output rate. Good for traffic shaping.
🪟
Fixed Window
Simple counter per time window. Resets at boundary. Vulnerable to burst at window edge — double rate attack possible.
🔄
Sliding Window
Rolling window with timestamp log or weighted hybrid. No boundary problem. Higher memory but most accurate. Preferred for strict APIs.
04 — Deep Dive

Token Bucket Algorithm

Token Bucket — How It Works
⚙️ Key Parameters
  • Capacity (C) — max tokens bucket holds = max burst size
  • Refill Rate (R) — tokens added per second = sustained rate
  • Current Tokens (T) — available tokens at any instant
  • Last Refill Time — timestamp of last token addition
✅ Pros & ❌ Cons
  • + Allows bursting up to capacity
  • + Simple and memory efficient (2 values per user)
  • + Smooth average throughput control
  • − Race condition in distributed systems
  • − Burst could still overload downstream
🔢 Worked Example

Capacity = 10, Rate = 2 tokens/sec.
User sends 10 requests instantly → all pass (uses all 10 tokens).
At t=5s → 10 tokens refilled. Next 10 requests pass again.
Sustained throughput = 2 req/sec. Burst = 10 req at once.

public interface RateLimiterStrategy {

    /**
     * Check if a request from given key (userId / IP) is allowed.
     * @param key  identifier (e.g. userId, IP, apiKey)

// TokenBucketRateLimiter.java
// Strategy: tokens refill at R/sec, max capacity C
// Each request consumes 1 token
// ═══════════════════════════════════════════════════════

package com.example.ratelimiter;

import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicReference;

public class TokenBucketRateLimiter implements RateLimiterStrategy {

    /** Snapshot stored per user: (tokens, lastRefillNanoTime) */
    private record BucketState(double tokens, long lastNanos) {}

    private final double capacity;       // max tokens = max burst
    private final double refillRatePerNs; // tokens added per nanosecond
    private final ConcurrentHashMap<String, AtomicReference<BucketState>> buckets
        = new ConcurrentHashMap<>();

    /**
     * @param capacity        max tokens (burst capacity)
     * @param refillRatePerSec tokens added per second
     */
    public TokenBucketRateLimiter(int capacity, double refillRatePerSec) {
        this.capacity = capacity;
        this.refillRatePerNs = refillRatePerSec / 1_000_000_000.0;
    }

    @Override
    public boolean allowRequest(String key) {
        AtomicReference<BucketState> ref = buckets.computeIfAbsent(
            key, k -> new AtomicReference<>(
                new BucketState(capacity, System.nanoTime())
            )
        );

        // CAS loop — lock-free, thread-safe
        while (true) {
            BucketState current = ref.get();
            long now = System.nanoTime();

            // Compute refilled tokens since last check
            double elapsed = now - current.lastNanos();
            double refilled = elapsed * refillRatePerNs;
            double newTokens = Math.min(capacity, current.tokens() + refilled);

            if (newTokens < 1.0) {
                return false; // Not enough tokens — rate limited
            }

            BucketState updated = new BucketState(newTokens - 1.0, now);

            // Atomically update — retry if another thread changed state
            if (ref.compareAndSet(current, updated)) {
                return true;
            }
        }
    }

    public int getRemainingTokens(String key) {
        AtomicReference<BucketState> ref = buckets.get(key);
        if (ref == null) return (int) capacity;
        BucketState s = ref.get();
        double elapsed = System.nanoTime() - s.lastNanos();
        return (int) Math.min(capacity, s.tokens() + elapsed * refillRatePerNs);
    }

    @Override
    public String getName() { return "TokenBucket"; }
}

// LeakyBucketRateLimiter.java
// Strategy: queue drains at fixed rate, overflow = reject
// No bursting — guarantees constant output rate
// ═══════════════════════════════════════════════════════

package com.example.ratelimiter;

import java.util.concurrent.ConcurrentHashMap;

public class LeakyBucketRateLimiter implements RateLimiterStrategy {

    private static class BucketState {
        double queueSize;    // current requests in queue
        long   lastLeakNanos;
        BucketState(double q, long t) { queueSize = q; lastLeakNanos = t; }
    }

    private final double capacity;      // max queue depth
    private final double leakRatePerNs; // requests drained per nanosecond
    private final ConcurrentHashMap<String, BucketState> buckets
        = new ConcurrentHashMap<>();

    public LeakyBucketRateLimiter(int capacity, double leakRatePerSec) {
        this.capacity = capacity;
        this.leakRatePerNs = leakRatePerSec / 1_000_000_000.0;
    }

    @Override
    public synchronized boolean allowRequest(String key) {
        long now = System.nanoTime();
        BucketState state = buckets.computeIfAbsent(
            key, k -> new BucketState(0, now)
        );

        // Drain queue based on elapsed time
        double elapsed = now - state.lastLeakNanos;
        double leaked  = elapsed * leakRatePerNs;
        state.queueSize    = Math.max(0, state.queueSize - leaked);
        state.lastLeakNanos = now;

        if (state.queueSize < capacity) {
            state.queueSize++;  // Enqueue request
            return true;
        }
        return false; // Overflow — drop request
    }

    @Override
    public String getName() { return "LeakyBucket"; }
}

// FixedWindowRateLimiter.java
// Strategy: count requests per time window; reset at boundary
// ⚠️ Weakness: double-rate burst at window boundary
// ═══════════════════════════════════════════════════════

package com.example.ratelimiter;

import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;
importspan>import java.util.concurrent.atomic.AtomicLong;

public class FixedWindowRateLimiter implements RateLimiterStrategy {

    private static class WindowState {
        AtomicInteger count = new AtomicInteger(0);
        AtomicLong    windowStart = new AtomicLong(System.currentTimeMillis());
    }

    private final int  limit;
    private final long windowMs;
    private final ConcurrentHashMap<String, WindowState> windows
        = new ConcurrentHashMap<>();

    public FixedWindowRateLimiter(int limit, long windowSeconds) {
        this.limit    = limit;
        this.windowMs = windowSeconds * 1000;
    }

    @Override
    public boolean allowRequest(String key) {
        WindowState ws = windows.computeIfAbsent(key, k -> new WindowState());
        long now = System.currentTimeMillis();

        // Check if current window has expired
        if (now - ws.windowStart.get() >= windowMs) {
            // Reset window atomically
            ws.windowStart.set(now);
            ws.count.set(0);
        }

        // Increment and check limit (getAndIncrement is atomic)
        return ws.count.getAndIncrement() < limit;
    }

    @Override
    public String getName() { return "FixedWindow"; }
}

// SlidingWindowRateLimiter.java
// Strategy: timestamp log within rolling window
// Most accurate — no boundary spike problem
// ═══════════════════════════════════════════════════════

package com.example.ratelimiter;

import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

public class SlidingWindowRateLimiter implements RateLimiterStrategy {

    private final int  limit;
    private final long windowMs;

    // Per user: sorted deque of request timestamps
    private final ConcurrentHashMap<String, Deque<Long>> logs
        = new ConcurrentHashMap<>();

    public SlidingWindowRateLimiter(int limit, long windowSeconds) {
        this.limit    = limit;
        this.windowMs = windowSeconds * 1000;
    }

    @Override
    public synchronized boolean allowRequest(String key) {
        long now = System.currentTimeMillis();
        long windowStart = now - windowMs;

        Deque<Long> log = logs.computeIfAbsent(key, k -> new ArrayDeque<>());

        // Remove timestamps outside the rolling window
        while (!log.isEmpty() && log.peekFirst() <= windowStart) {
            log.pollFirst();
        }

        if (log.size() < limit) {
            log.addLast(now);  // Record this request timestamp
            return true;
        }
        return false; // Window full
    }

    @Override
    public String getName() { return "SlidingWindowLog"; }
}

// RateLimiterService.java
// Shows how a real service uses multiple strategies:
//  - IP-level:    FixedWindow (cheap, fast)
//  - User-level:  TokenBucket (burst friendly)
//  - API key:     SlidingWindow (accurate)
//  - Global:      LeakyBucket (traffic shaping)
// ═══════════════════════════════════════════════════════

package com.example.ratelimiter;

import java.util.Map;

public class RateLimiterService {

    // Strategies for different contexts
    private final RateLimiterStrategy ipLimiter;
    private final RateLimiterStrategy userLimiter;
    private final RateLimiterStrategy apiKeyLimiter;
    private final RateLimiterStrategy globalLimiter;

    // Tier-based limits (loaded from config / DB)
    private static final Map<String, Integer> TIER_LIMITS = Map.of(
        "free",       100,
        "pro",        1000,
        "enterprise", Integer.MAX_VALUE
    );

    public RateLimiterService() {
        // IP: max 60 req/min per IP (fixed window, cheap)
        this.ipLimiter = new FixedWindowRateLimiter(60, 60);

        // User: burst of 20, 5 req/sec sustained (token bucket)
        this.userLimiter = new TokenBucketRateLimiter(20, 5);

        // API key: 1000 req/hour accurate (sliding window)
        this.apiKeyLimiter = new SlidingWindowRateLimiter(1000, 3600);

        // Global: 10000 req/sec throughput cap (leaky bucket)
        this.globalLimiter = new LeakyBucketRateLimiter(500, 10000);
    }

    /**
     * Main entry point — called by filter/interceptor for every request.
     * @return RateLimitResult with allowed flag + metadata for response headers
     */
    public RateLimitResult checkRequest(String userId, String ipAddress,
                                          String apiKey, String userTier) {
        // 1. Global service-wide cap (protects all downstream)
        if (!globalLimiter.allowRequest("global")) {
            return RateLimitResult.deny(100, globalLimiter.getName());
        }

        // 2. IP-level (blocks floods from single IPs)
        if (!ipLimiter.allowRequest(ipAddress)) {
            return RateLimitResult.deny(60_000, ipLimiter.getName());
        }

        // 3. Tier check — enterprise bypasses further limits
        if ("enterprise".equals(userTier)) {
            return RateLimitResult.allow(Integer.MAX_VALUE, "no-limit");
        }

        // 4. API key limit (per-key billing enforcement)
        if (apiKey != null && !apiKeyLimiter.allowRequest(apiKey)) {
            return RateLimitResult.deny(3_600_000, apiKeyLimiter.getName());
        }

        // 5. User-level limit (per-account burst control)
        if (userId != null && !userLimiter.allowRequest(userId)) {
            return RateLimitResult.deny(200, userLimiter.getName());
        }

        return RateLimitResult.allow(99, "passed-all-layers");
    }
}


// ═══════════════════════════════════════════════════════
// RateLimiterFilter.java  (Spring Boot / Jakarta)
// Intercepts every HTTP request before it hits the controller
// ═══════════════════════════════════════════════════════

@Component
public class RateLimiterFilter implements Filter {

    @Autowired
    private RateLimiterService rateLimiterService;

    @Override
    public void doFilter(ServletRequest req, ServletResponse res,
                          FilterChain chain) throws IOException, ServletException {
        HttpServletRequest  request  = (HttpServletRequest)  req;
        HttpServletResponse response = (HttpServletResponse) res;

        String userId   = request.getHeader("X-User-Id");
        String ip       = request.getRemoteAddr();
        String apiKey   = request.getHeader("X-Api-Key");
        String userTier = request.getHeader("X-User-Tier");

        RateLimitResult result = rateLimiterService.checkRequest(
            userId, ip, apiKey, userTier
        );

        // Set standard rate limit response headers
        response.setHeader("X-RateLimit-Remaining",
            String.valueOf(result.remainingTokens()));
        response.setHeader("X-RateLimit-Strategy", result.strategy());

        if (!result.allowed()) {
            response.setHeader("Retry-After",
                String.valueOf(result.retryAfterMs() / 1000));
            response.sendError(429, "Too Many Requests");
            return;
        }

        chain.doFilter(req, res); // Pass to next filter / controller
    }
}
06 — Comparison

Algorithm Comparison

Algorithm Burst? Memory Accuracy Distributed? Best For
🪙 Token Bucket YES O(1) High Atomic CAS APIs, user-level limits
🪣 Leaky Bucket NO O(1) High Needs sync Traffic shaping, smooth output
🪟 Fixed Window Edge only O(1) Medium Easy (Redis INCR) Simple quotas, internal tools
🔄 Sliding Window Controlled O(N) per user Very High Redis ZSET Strict public APIs
🌐 Distributed System Notes
  • Use Redis + Lua scripts for atomic multi-key operations
  • INCR + EXPIRE = Fixed Window in Redis
  • ZADD + ZCOUNT = Sliding Window in Redis
  • Token Bucket: store tokens:userId as float in Redis
  • Always set TTL to avoid memory leaks
📋 Interview Cheatsheet
  • Interviewer says "allow bursts" → Token Bucket
  • Interviewer says "smooth output" → Leaky Bucket
  • Interviewer says "simple quota" → Fixed Window
  • Interviewer says "most accurate" → Sliding Window
  • Always mention: Redis, atomic ops, response headers (X-RateLimit-*)
🔑 Key HTTP Headers to Return
  • X-RateLimit-Limit — total allowed requests in window
  • X-RateLimit-Remaining — requests left in current window
  • X-RateLimit-Reset — epoch time when window resets
  • Retry-After — seconds until client can retry (on 429)
